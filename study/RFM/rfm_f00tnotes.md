# f00tnotes: 로봇 파운데이션 모델(RFM) 용어 글로서리

> 'The Data Problem' 에세이에 나오는 용어 중 일반 독자가 모를 만한 것을 가볍고 쉬운 말로 풀어 둔 카드 모음.
> 각 카드는 독립적이다. **Hover** 한 줄이 접힌 팝업에 보이고, 나머지는 카드를 열면 펼쳐진다.
> 카드 형식: `slug`(링크용) | 카테고리 | 난이도 | hover 한 줄 | 미니 인포그래픽 | 쉬운 설명 | 이 글에서 왜 나오는가.
> 원칙: 한 카드는 8문장을 넘지 않는다. 전문가든 아니든 한 번에 이해되게 쓴다.

## 큰 그림 (마스터 인포그래픽)

RFM의 각 용어가 어디에 위치하는지. 정보는 왼쪽에서 오른쪽으로 흐른다.

```
 데이터를 만든다       모델이 배운다          몸에 올린다        현장에 나간다       사업이 된다
 -------------       ------------          ----------        -----------       ----------
 [텔레오퍼레이션]      [VLA]                 [휴머노이드]        [Sim2Real 갭]     [모델 전용형]
 [시뮬레이션]         [Diffusion Policy]    [매니퓰레이터/4족]  [Embodiment 갭]   [수직통합형]
 [trajectory]       [계층형 System 1/2]    [end-effector]    [zero-shot]      [데이터 인프라형]
 [도메인 데이터]       [월드 모델]            [proprioception]                   [RaaS]

        파운데이션 모델(RFM)이 가운데 있고, 'Physical AI'는 이 전체를 묶는 상위 개념이다.
        commoditization / moat 가 누가 가치를 지키는지 설명한다.
```

## A. 기초 개념

### 로봇 파운데이션 모델 (RFM)
`slug: rfm` | 카테고리: Core | 난이도: ★★☆

> **Hover:** 말로 시키고 눈으로 본 걸 받아, 로봇의 행동을 출력하는 범용 AI 모델. 로봇판 GPT를 노린다.

```
"식탁 좀 치워줘" + 카메라 영상 -> [ RFM ] -> 팔 관절을 어떻게 움직일지
```

**무엇인가.** RFM은 대규모의 영상-언어-행동 데이터로 미리 학습된 하나의 정책 모델이다. 자연어 지시와 카메라 영상, 관절 상태를 입력받아 로봇이 어떻게 움직일지를 출력한다. LLM이 텍스트에서 범용성을 얻은 것처럼, 로봇 행동에서 범용성을 얻으려는 시도다. 'RFM'이라는 말은 Covariant가 2024년 RFM-1을 공개하며 퍼졌다.

**이 글에서.** 글 전체가 RFM 스택의 어느 층에 해자가 있는지를 다룬다.

---

### Physical AI (피지컬 AI)
`slug: physical-ai` | 카테고리: Core | 난이도: ★☆☆

> **Hover:** 화면 속이 아니라 실제 물리 세계에서 움직이고 일을 하는 AI를 묶는 상위 개념.

```
디지털 AI:  글을 쓰고 그림을 그린다 (화면 안)
Physical AI: 물건을 집고 조립하고 청소한다 (현실 세계)
```

**무엇인가.** Physical AI는 챗봇처럼 화면 안에 머무는 AI가 아니라, 로봇이라는 몸을 통해 실제 세계에 손을 대는 AI를 가리키는 큰 범주다. RFM은 이 Physical AI를 구동하는 두뇌에 해당한다. 휴머노이드, 농기계, 산업 로봇이 모두 여기 속한다.

**이 글에서.** RFM 투자 붐을 묶어 부르는 시장 용어로 등장한다.

---

### VLA (Vision-Language-Action)
`slug: vla` | 카테고리: 모델 | 난이도: ★★★

> **Hover:** 영상과 말을 토큰으로 바꿔 한 모델에 넣고, 곧장 행동을 뽑아내는 방식.

```
[카메라 영상] + [지시 문장] -> 토큰으로 변환 -> [Transformer] -> [행동 토큰]
```

**무엇인가.** VLA는 영상(Vision)과 언어(Language)를 하나의 토큰 시퀀스로 합쳐 모델에 넣고, 행동(Action)을 바로 디코딩하는 단일 정책 구조다. LLM이 텍스트를 토큰으로 다루듯, 로봇의 보고-듣고-움직이는 과정을 한 모델 안에서 처리한다. Google RT-2, Figure Helix, OpenVLA가 대표 사례다.

**이 글에서.** 모델 층의 표준 아키텍처로 언급된다.

---

### Diffusion Policy (확산 정책)
`slug: diffusion-policy` | 카테고리: 모델 | 난이도: ★★★

> **Hover:** 그림 생성 AI가 쓰는 기법을 빌려, 로봇 행동을 노이즈에서 점점 다듬어 만들어 내는 방식.

```
무작위 노이즈 -> 조금씩 다듬기 -> 조금씩 다듬기 -> 매끄러운 행동 궤적
```

**무엇인가.** Diffusion Policy는 이미지 생성에 쓰이는 확산 모델을 로봇 행동에 적용한 방식이다. 행동을 하나로 딱 정하지 않고 가능한 행동의 분포로 학습해, 같은 상황에서 여러 자연스러운 동작을 표현할 수 있다. 그래서 미세하고 다양한 조작에 강점이 있다. Toyota Research의 연구에서 시작됐고 Physical Intelligence의 π0가 이 계열이다.

**이 글에서.** VLA와 함께 RFM 모델 계열을 나누는 한 축이다.

---

### 계층형 아키텍처 (System 1 / System 2)
`slug: hierarchical` | 카테고리: 모델 | 난이도: ★★★

> **Hover:** 느리게 생각하는 뇌(추론)와 빠르게 움직이는 뇌(모터 제어)를 나눠 둔 구조.

```
System 2 (느림): "무엇을 할지" 추론 - VLM
        |
System 1 (빠름): "어떻게 움직일지" 모터 제어
```

**무엇인가.** 계층형은 사람의 빠른 직관(System 1)과 느린 사고(System 2)에 빗댄 구조다. 상위 모델이 영상과 지시를 보고 무엇을 할지 천천히 추론하면, 하위 정책이 그 계획을 받아 관절을 빠르게 제어한다. Figure의 Helix와 NVIDIA GR00T가 이 방식을 쓴다.

**이 글에서.** 수직통합형 휴머노이드의 모델 설계로 언급된다.

---

### 월드 모델 (World Model)
`slug: world-model` | 카테고리: 모델 | 난이도: ★★★

> **Hover:** 행동을 배우기 전에, 세상이 어떻게 움직이는지부터 머릿속에 학습해 두는 방식.

```
"이 컵을 밀면 -> 굴러가서 -> 떨어진다"  를 미리 안 뒤에 행동을 계획
```

**무엇인가.** 월드 모델은 환경의 물리 법칙과 인과(밀면 굴러간다)를 먼저 학습한 뒤, 그 위에서 행동 정책을 미세조정하는 접근이다. 직접 해 보지 않고도 머릿속 시뮬레이션으로 결과를 예측할 수 있어 데이터 효율이 높다. World Labs, DeepMind Genie 등이 이 방향이다.

**이 글에서.** RFM 모델 계열을 나누는 네 번째 축으로 등장한다.

---

## B. 데이터와 학습

### 텔레오퍼레이션 시연 (Teleoperation Demonstration)
`slug: teleoperation` | 카테고리: 데이터 | 난이도: ★★☆

> **Hover:** 사람이 로봇 팔을 직접 원격 조종해, 올바른 행동을 한 번 한 번 시범 보이는 일. 가장 비싼 데이터.

```
사람이 조종기로 로봇 팔 조작 -> 그 움직임을 기록 -> 모델의 학습 정답지
```

**무엇인가.** 텔레오퍼레이션 시연은 사람이 로봇을 직접 조종해 작업을 해 보이고, 그 궤적을 학습 데이터로 모으는 방식이다. 가장 정확하지만 사람이 일일이 만들어야 해서 가장 비싸고 느리다. 로봇 데이터가 부족한 근본 이유가 여기 있다. 인터넷에 그냥 쌓여 있는 텍스트와 달리, 행동 데이터는 누군가 손으로 만들어야 한다.

**이 글에서.** "로봇은 인터넷이라는 행운이 없다"는 데이터 부족 논점의 핵심이다.

---

### Trajectory / RT-X 데이터셋
`slug: trajectory` | 카테고리: 데이터 | 난이도: ★★☆

> **Hover:** trajectory는 작업 하나를 처음부터 끝까지 한 동작의 기록. RT-X는 그걸 모은 대표 공개 데이터셋.

```
LLM 학습:  수조(兆) 토큰
RFM 학습:  RT-X 약 100만 trajectory, π0 약 1만 시간   <- 6~7자릿수 부족
```

**무엇인가.** Trajectory는 로봇이 한 작업을 수행한 처음부터 끝까지의 행동 기록 한 묶음이다. RT-X는 여러 연구실의 trajectory를 합친 대표적 공개 데이터셋으로 100만 건 수준이다. 수조 토큰을 먹는 LLM과 비교하면 로봇 데이터는 자릿수가 한참 모자란다. 이 규모 격차가 RFM의 가장 큰 병목이다.

**이 글에서.** 데이터 부족이 "자릿수의 문제"라는 주장의 근거 수치다.

---

### Sim2Real Gap (시뮬-실제 격차)
`slug: sim2real` | 카테고리: 데이터 | 난이도: ★★★

> **Hover:** 시뮬레이션에서 잘하던 로봇이 진짜 세계에 나오면 성능이 떨어지는 현상.

```
시뮬레이션 속:  100점 (마찰, 빛, 소음이 완벽)
실제 환경:      70점  (예상 못 한 변수투성이)
        이 차이를 메우는 게 Sim2Real
```

**무엇인가.** 시뮬레이션은 값싸게 데이터를 대량 생산할 수 있지만, 가상 환경은 실제 세계의 마찰, 조명, 센서 노이즈를 완벽히 재현하지 못한다. 그래서 시뮬에서 학습한 정책이 현실에서 그대로 통하지 않고 성능이 떨어진다. 이 차이를 줄이는 일을 Sim2Real이라 부른다. RFM 4대 난제 중 하나다.

**이 글에서.** 값싼 시뮬 데이터를 실제로 쓰려면 건너야 하는 다리로 설명된다.

---

### Embodiment Gap (하드웨어 이질성)
`slug: embodiment-gap` | 카테고리: 데이터 | 난이도: ★★★

> **Hover:** A 로봇으로 배운 모델을, 팔 길이도 손가락 수도 다른 B 로봇에 그대로 옮기기 어려운 문제.

```
학습한 몸:  팔 2개, 손가락 5개
새로운 몸:  팔 1개, 집게형 손   ->  배운 게 안 맞는다
```

**무엇인가.** Embodiment Gap은 모델이 학습된 로봇과 형태가 다른 로봇으로 옮겨질 때 생기는 문제다. 관절 수, 팔 길이, 손 모양이 다르면 같은 행동 명령이 다른 결과를 낸다. 모델 회사들이 "어떤 몸에든 옮겨 쓸 수 있다"를 강조하는 건 바로 이 격차를 넘었다고 주장하는 것이다.

**이 글에서.** Skild의 "One brain, any body" 슬로건이 가리키는 문제다.

---

### Zero-shot Generalization (제로샷 일반화)
`slug: zero-shot` | 카테고리: 데이터 | 난이도: ★★☆

> **Hover:** 한 번도 배운 적 없는 새 물건이나 새 환경에서, 추가 학습 없이 곧장 일을 해내는 능력.

```
학습 안 한 에어프라이어  ->  그래도 열고 닫는다  (zero-shot 성공)
```

**무엇인가.** Zero-shot은 학습 데이터에 없던 상황을 추가 훈련 없이 바로 처리하는 능력이다. 모델이 진짜로 범용적인지 보여 주는 핵심 지표다. Physical Intelligence의 π0.5는 처음 보는 가정에서 청소를, π0.7은 거의 본 적 없는 에어프라이어 조작을 zero-shot으로 해냈다고 시연했다.

**이 글에서.** 모델 능력이 빠르게 좋아지고 표준화되고 있다는 증거로 등장한다.

---

### Fine-tuning (파인튜닝)
`slug: fine-tuning` | 카테고리: 데이터 | 난이도: ★★☆

> **Hover:** 이미 학습된 범용 모델을, 내 현장 데이터로 추가 훈련해 우리 작업에 맞게 다듬는 일.

```
범용 RFM  +  우리 공장 데이터  ->  우리 공정 전용 모델
```

**무엇인가.** Fine-tuning은 큰 비용으로 미리 학습된 범용 모델을, 특정 도메인의 적은 데이터로 추가 훈련해 그 현장에 맞추는 작업이다. 모델 자체를 처음부터 만들지 않고도 자기 데이터로 차별화할 수 있는 지점이다. Carbon Robotics는 새 잡초를 며칠이 아니라 몇 분 안에 fine-tuning하는 워크플로우로 강점을 만들었다.

**이 글에서.** 한국이 베팅해야 할 application 레이어의 핵심 무기로 제시된다.

## C. 하드웨어와 형태

### 휴머노이드 (Humanoid)
`slug: humanoid` | 카테고리: 하드웨어 | 난이도: ★☆☆

> **Hover:** 사람을 닮은 두 발 로봇. 사람이 쓰는 환경을 그대로 쓰려고 사람 형태를 택한다.

```
사람용으로 만든 세상(문, 계단, 도구)  ->  사람 모양 로봇이 그대로 사용
```

**무엇인가.** 휴머노이드는 사람과 비슷한 몸통, 팔, 다리를 가진 로봇이다. 굳이 사람 모양인 이유는 세상이 이미 사람에 맞춰 만들어져 있어서, 환경을 바꾸지 않고 그대로 투입할 수 있기 때문이다. Figure, 1X, Tesla Optimus가 대표 사례다. 다만 자본이 가장 많이 드는 형태이기도 하다.

**이 글에서.** 자본을 태우는 수직통합형 층의 대표 형태로 나온다.

---

### 매니퓰레이터 / 4족 로봇
`slug: form-factors` | 카테고리: 하드웨어 | 난이도: ★☆☆

> **Hover:** 매니퓰레이터는 공장의 로봇 팔, 4족은 개처럼 네 다리로 걷는 로봇. 휴머노이드 말고도 몸은 많다.

```
매니퓰레이터: 고정된 로봇 팔 (조립, 용접)
4족 로봇:     네 다리 보행 (점검, 순찰)
휴머노이드:   두 발 (사람 환경 범용)
```

**무엇인가.** RFM이 올라갈 수 있는 로봇 형태는 여러 가지다. 매니퓰레이터는 한자리에 고정된 산업용 로봇 팔이고, 4족 로봇은 험지를 걷는 데 강하다. 모델 전용형 회사들이 노리는 건 이 모든 형태에 같은 정책을 올리는 것이다.

**이 글에서.** "any body"가 가리키는 다양한 몸들로 언급된다.

---

### proprioception (고유수용감각) / end-effector
`slug: proprioception` | 카테고리: 하드웨어 | 난이도: ★★★

> **Hover:** proprioception은 로봇이 느끼는 자기 관절의 위치/각도. end-effector는 팔 끝에 달린 손이나 집게.

```
proprioception: "지금 내 팔꿈치는 90도로 굽어 있다"  (자기 몸 감각)
end-effector:   팔 맨 끝의 손/집게/도구  (실제로 물건에 닿는 부분)
```

**무엇인가.** Proprioception은 사람이 눈을 감고도 팔 위치를 아는 것처럼, 로봇이 자기 관절 상태를 인식하는 감각이다. RFM의 입력 중 하나가 이 관절 상태값이다. End-effector는 로봇 팔 맨 끝에 달려 실제로 물건과 접촉하는 부분으로, 손이나 집게, 특수 도구가 될 수 있다.

**이 글에서.** RFM의 입력과 출력을 설명할 때 배경이 되는 용어다.

---

## D. 사업과 시장

### 사업 모델 3분류 (모델 전용형 / 수직통합형 / 데이터 인프라형)
`slug: business-models` | 카테고리: 사업 | 난이도: ★★☆

> **Hover:** RFM 회사는 셋으로 갈린다. 모델만, 하드웨어까지, 아니면 데이터만.

```
모델 전용형:   모델만 만듦 (PI, Skild, RLWRLD)    - compute 의존, 자본효율 낮음
수직통합형:    하드웨어+모델 (Figure, 1X, Tesla)  - CapEx 폭발
데이터 인프라형: 데이터만 (Config, Carbon)         - 자본효율 중, 매출 가능
```

**무엇인가.** RFM 시장은 세 갈래로 나뉜다. 모델 전용형은 정책 모델에만 집중하고 하드웨어는 파트너에 맡긴다. 수직통합형은 하드웨어와 모델을 둘 다 직접 만든다. 데이터 인프라형은 모델도 하드웨어도 만들지 않고 학습 데이터를 모아 공급한다. 자본 효율과 방어 가능성이 셋이 크게 다르다.

**이 글에서.** 어느 층에 베팅해야 하는가라는 글의 뼈대다.

---

### Robot-as-a-Service (RaaS)
`slug: raas` | 카테고리: 사업 | 난이도: ★★☆

> **Hover:** 로봇 두뇌를 클라우드에서 빌려 쓰는 방식. 로봇 안에 비싼 GPU를 넣지 않아도 된다.

```
로봇  --질문-->  [클라우드의 RFM]  --행동 명령-->  로봇
        (온보드 GPU 없이 호출)
```

**무엇인가.** RaaS는 RFM을 로봇 몸체에 직접 넣지 않고 클라우드에서 호스팅해, 로봇이 네트워크로 호출해 쓰는 사업 모델이다. 로봇마다 값비싼 GPU를 달지 않아도 돼 비용이 낮아진다. Config이 자사 파운데이션 모델을 이런 형태로 출시할 계획이다.

**이 글에서.** 데이터 인프라형이 매출을 만드는 방식으로 등장한다.

---

### Commoditization (commodity화)
`slug: commoditization` | 카테고리: 사업 | 난이도: ★★☆

> **Hover:** 특별하던 것이 어디서나 싸게 살 수 있는 흔한 물건이 되는 흐름. 사는 쪽엔 좋고 파는 쪽엔 마진 압박.

```
희소하고 특별함  ---- 시간이 지나면 ---->  싸고 어디서나 살 수 있음
(높은 값, 우위)                          (낮은 값, 우위 없음)
```

**무엇인가.** Commoditization은 한때 드물고 차별적이던 것이 표준화되어 누구나 싸게 살 수 있게 되는 과정이다. 이 글은 RFM의 모델 능력이 이 길을 가고 있다고 본다. 모두가 같은 몇 개 모델을 빌려 같은 품질을 살 수 있으면, 그건 더 이상 우위가 아니다. 가치는 아직 commodity가 되지 않은 것으로 옮겨 간다.

**이 글에서.** "모델은 commodity, 데이터는 moat"라는 주장의 엔진이다.

---

### Moat (해자)
`slug: moat` | 카테고리: 사업 | 난이도: ★★☆

> **Hover:** 경쟁자가 따라 하기 어렵게 만드는 것. 성을 둘러싼 물길처럼, 넓을수록 사업이 안전하다.

```
성 = 당신의 사업
해자 = 경쟁자가 복제 못 하게 막는 것 (독자 데이터, 락인, 규모)
넓은 해자 -> 안전한 사업
```

**무엇인가.** Moat는 경쟁으로부터 사업을 지켜 주는 지속적 우위로, 성을 두른 해자에서 따온 말이다. 강한 브랜드, 독자 데이터, 높은 교체 비용이 흔한 예다. 이 글의 논점 전체는 RFM 스택에서 진짜 해자가 되는 층이 어디냐는 질문이다. 답은 시간이 지날수록 복리로 쌓이는 데이터다.

**이 글에서.** 제목 'The Data Problem'이 던지는 핵심 질문이 여기 산다.
